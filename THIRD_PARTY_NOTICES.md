# Third-party notices and license review

The proposed Apache-2.0 license applies only if the owner approves it. Third-party code keeps its own terms. The exact proposal is in [licenses/Apache-2.0.proposed.txt](licenses/Apache-2.0.proposed.txt); the source license terms are published by the [Apache Software Foundation](https://www.apache.org/licenses/LICENSE-2.0.txt). This is a preparation inventory, not a claim of legal clearance.

The [npm inventory](licenses/npm-inventory.json) records all 288 locked external occurrences across both npm lockfiles, exact versions/integrities, optional-platform installation state and the license/notice texts collected from installed Linux x86_64 packages. Repeated nested packages are retained. The lock graph reports MIT, Apache-2.0, MPL-2.0, ISC, BSD-3-Clause, 0BSD and MIT OR Apache-2.0. One tooling dependency (`memorystream` 0.3.1) lacks singular lockfile license metadata. Its installed plural `licenses` field and bundled LICENSE both identify MIT; the inventory records that evidence separately without rewriting the lock. A package's declared license alone is not a complete notice audit.

The locked accessibility and CSS tooling includes MPL-2.0 components (axe-core and Lightning CSS). Preserve file-level licenses and source availability obligations for any covered distributed modifications/binaries; do not relicense third-party code as Dispatch. The pinned Anvil package declares `MIT OR Apache-2.0`; its binary's full upstream notice/source obligations still require review before redistribution. No dependency binary, browser, node_modules directory or container image is included in this source tree. Installed packages without a bundled top-level license are identified by an empty `notice_files` list. The [upstream inventory](licenses/upstream-inventory.json) covers the 13 packages originally missing bundled top-level texts. Exact source notices have now been collected for 12: four at npm `gitHead` revisions, two at source tags with matching package name/version, and six at source commits bound by npm provenance to the exact package integrity. Both installed lock graphs passed `npm audit signatures`; all original notice texts and duplicate package occurrences remain preserved. **One source-attribution gap remains: `react-remove-scroll-bar` 2.3.8.** Its published source commit and matching version tags could not supply the exact upstream text; do not treat its MIT metadata as completed notice clearance. Resolve this before public distribution.

The edge image builds Caddy 2.11.7 with the checked-in Go module graph and fixed Go toolchain. `infra/caddy-security/go.mod` changes the upstream dependency selection, including `golang.org/x/net` 0.60.0; these are modified build inputs, not an unmodified upstream binary claim. The image retains Caddy, Go and x/net license texts. A complete transitive Go-module and OS-image notice/source-offer audit is still required before distributing images; this source candidate is not permission to distribute those images. Preserve the pinned source recipes and checksum metadata.

The Python validator requirements are exact version pins, not a bundled interpreter or library distribution. Their notice obligations must be checked if bundling those tools. The original sample text in `examples/assets/guide.txt` was created for the local demonstration and contains no vendor asset. No customer logos, stock artwork or historical private screenshots are included.

Owner approval must resolve project copyright attribution, license choice and remaining third-party obligations. See [licensing preparation](licenses/README.md).

The complete Apache proposal was checked byte-for-byte against the official text during final preparation. All 288 lock occurrences and 235 original notice-file references matched the checked-in inventory. Additional upstream texts have separate source URLs and SHA-256 bindings in the upstream inventory. See [SPDX and attribution preparation](licenses/README.md); owner approval and the stated missing-source/binary review remain open.
